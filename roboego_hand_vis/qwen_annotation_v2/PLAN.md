# 千问时序上下文与可控并发

目标：借鉴 Argus 的连续时间上下文、并发任务和明确的时间映射，保留千问接口、任务信息约束与原帧字段。

- 按现有 batch_size 划分独占目标帧，前后各加 overlap_frames 作为只读上下文；请求允许包含上下文标签但保存时只保留目标帧。
- 校验返回时间点完整、唯一且属于输入窗口；顺序可不同，保存时按输入时间归一并排序，缺帧、额外时间或重复帧按校验失败重试。
- max_concurrency 控制同时请求数，worker 只读图片和发请求，主线程独占 batch/checkpoint/chunk 写回。有限在途任务；失败不阻止其余批次保存。
- 独立 V2 YAML 推荐 batch_size=10、overlap_frames=2、max_concurrency=3。旧模块及原配置完全不修改。
- 基础时间点与核心分组保持原始视频相对时间，不在跳跃的有效窗口之间增加上下文。
- 抽帧按小数时间生成唯一文件名，整数时间保留旧文件名；不修改旧下游流程。
- 断点设置保存到 raw/run_settings.json，记录采样及提示词、视频身份；修改并发不会改变分组身份，修改采样/重叠需新产出目录。既有旧结果不自动导入 V2，需要新的输出目录。
- 原始恢复按相同批次时间计划过滤上下文标签，不能把缺帧 raw 标为已完成。
- Summary 增加实际运行时间和并发/上下文参数；不承诺真实模型速度或动作连贯性，需实际 session 对比。

按 TDD 完成抽帧回归、时序批次核心覆盖、并发乱序写回、失败重试、断点设置与恢复测试，再跑全量测试。借鉴设计而不复制 Argus 源码，V2 支持独立图片和可选带时间标签拼图，不更改旧代码、数据库和同步流程。

用户确认将所有新标注实现隔离在 qwen_annotation_v2；使用独立输出目录对比，暂为单视频实验入口，不写业务数据库。
