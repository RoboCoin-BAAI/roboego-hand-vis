# L1 download implementation plan

**Goal:** Provide direct KS3 downloads and optional database-backed L1 downloads.

**Design:** `download_data/downloader.py` owns KS3 subprocess execution and
filesystem publication, with no database imports. `database_adapter.py` owns task
claiming and status writeback through a service protocol. `l1.py` chooses direct
or database mode; it imports the database package only in database mode.
Rename the previous `downoad_data` directory to `download_data` and preserve the
local ignored KS3 binaries/configuration. All user-facing examples use relative
or placeholder paths.

**Behavior:** Direct mode accepts KS3 session prefixes. Database mode is explicitly
selected by `--database`, reads DATABASE_URL, and claims only pending l1data rows.
Both download into a temporary directory under the specified shared output root,
validate exit status, failed-item manifests, and nonempty payload, then publish
`<output-root>/<session-name>` by directory rename. A receipt records the source
and local file sizes; matching completed directories can be reused. Existing
unverified directories are never silently overwritten. Failed downloads retain
temporary data/logs and become failed in database mode. A failed database writeback
stops the worker. Multiple workers use DB claims and a shared destination lock.
There is no automatic reset of active database tasks.
